# CLAUDE.md

Expo app (phone + Android TV) that pulls Videos from the LearnifyTube desktop app over local WiFi and plays them, including Offline.

## Commands

```bash
npm start                   # Expo dev server (phone surface)
npm run start:tv            # Expo dev server forced to TV surface
npm run android             # Run on Android emulator
npm run type-check
npm run lint
npm run check:ui-boundaries # Phone/TV route isolation check
npm test                    # jest-expo
```

Verify with `test`, `type-check`, `lint`, and `check:ui-boundaries`. Tests exercise modules through their public interface with a fake platform built via the module's factory; no module mocking.

Phone/TV UI against an isolated desktop: `.cursor/skills/verify/SKILL.md`. AVDs are `LearnifyPhone` and `LearnifyTV` (`npm run emulator:phone` / `emulator:tv`).

## Two Surfaces

`app/index.tsx` redirects to `app/(mobile)` or `app/(tv)` via `getAppSurface()` (`core/hooks/useAppSurface.ts`: `EXPO_PUBLIC_APP_SURFACE`, else `Platform.isTV`).

- `app/(mobile)` — phone: Home catalog (with On this phone section), Discover, Settings, player, pairing, share (P2P).
- `app/(tv)` — Android TV: d-pad navigation, player with overlay controls, channel browsing.

On the TV, hardware Back goes through one handler that `app/(tv)/_layout.tsx` mounts (`components/tv/tvBack.ts`): it pops the stack, lands on the TV home when there's nothing to pop, and exits from the home screen. A screen takes Back first with `useTVBackInterceptor` (the home grid, a channel's open playlist). `app/+native-intent.tsx` sends `learnify://` deep links into the TV group on the TV surface. Keep `predictiveBackGestureEnabled` off in `app.json`: with it on, Android 13–15 finish the activity on Back without telling JS.

The two route groups import and navigate only within themselves; `scripts/check-ui-boundaries.sh` enforces it. Put shared code in `components/`, `core/`, `services/`, `stores/`, or `db/`.

## Architecture

- **Desktop sync** — `services/api.ts` is the REST client for the desktop's mobile sync server; the version handshake lives in `apps/shared/mobile-sync-contract.ts`. It attaches the pairing code from `stores/connection.ts` to every request, and to image/video URLs as `?token=`; build desktop URLs with its `get*Url` helpers. A 401 surfaces as `PairingRequiredError`.
- **Desktop connection** — `services/desktop-connection/` owns the TV's connection to the desktop: `desktopConnection.useConnection()` (status `connecting` / `connected` / `offline` / `pairingRequired` / `incompatible`, the desktop's name, discovered desktops), `pair(code, address?)`, `connectManually(address)`, `retryNow()` and `disconnect()`. It tries the saved address, mDNS peers, the emulator host and the legacy port, retries with backoff (3 s up to 60 s) while in the foreground, and health-checks the desktop every 15 s; only that health check decides Offline mode. On the TV it publishes the connected desktop as the connection store's `serverUrl` (the saved address is `savedUrl`); `app/_layout.tsx` starts it on the TV surface only. The phone keeps the same `serverUrl` / `savedUrl` split: a persist merge never restores `serverUrl`, and `usePhoneDesktopHealth` probes `/info` every 15 s so Home filters to Offline copies when the desktop is down.
- **Downloads** — `services/download-queue/` owns the Download queue: `downloadQueue.request(video)` (does nothing if the Offline copy exists or the Download is on its way; retries a failed one), `cancel`, `waitUntilReady(videoId, signal)` (aborting stops the wait, not the Download), `getDownload`, and the `useDownload` / `useQueue` hooks. Inside, it waits for the desktop to fetch the Video, transfers two at a time with retry backoff, adds the Video to the library and hands the file to the Offline copy module's `adopt`; it runs only while the desktop is connected and the app is in the foreground (`app/_layout.tsx` starts it) and persists to AsyncStorage.
- **Video thumbnails** — `services/video-thumbnails/` stores each held Video's thumbnail as a file on the Device, so it shows in Offline mode: the Download queue stores it when a Download finishes, the Device mirror backfills held Videos missing one, and `stores/library.ts` removes it with the Video. Screens use `videoThumbnails.useLookup()` and fall back to the desktop URL when it returns null.
- **TV catalog** — `components/tv/tvCatalog.ts` `buildTVCatalog` decides the TV home tabs' cards, what each card opens, and the empty-state text. While connected it shows the desktop's catalog; otherwise (Offline mode, including `connecting` on a cold start) only collections, channels and History holding a Video with an Offline copy, and opening one plays only those Videos. My Lists starts with a "Sent to this TV" card for the On-device set, which the Device mirror keeps in `stores/onDeviceSet.ts` for Offline mode; while connected, card badges add how many of a card's Videos are "on this TV" (have an Offline copy). Its sibling `components/tv/tvChannel.ts` does the same for a channel screen: `heldChannelContents` (what the TV holds from the channel) and `buildTVChannelView` (the cards, what each opens or plays, the empty text), with the same rule; the screen only loads, keeps focus and renders.
- **Play queue** — `services/play-queue/` `playQueue.start({ id, title, videos, startIndex })` starts playing a list of Videos and returns the Video to open (null when the list is empty); on the TV it also records the queue in TV history (`stores/tvHistory.ts`). A queue started with a `collection` (a List or YouTube playlist) makes each Video that starts in it (`start`, then `videoStarted(id)` from the phone and TV players) that collection's Current Video (ADR-0006): kept in `stores/currentVideos.ts` (newest wins, with the desktop's from the collection endpoints), POSTed live to a desktop known (`desktopProtocol.known`) to speak `RESUME_SYNC_PROTOCOL_VERSION`, and carried by the Device report's `resume` group; a queue started anywhere else records nothing. `whereResumes` / `resume` apply the shared List rule (`apps/shared/list-pickup.ts`) for the phone collection screen's "Resume · title" and "Play from start". On the TV, every List or YouTube playlist queue starts with its `collection` (the TV home remembers what the collection endpoints name, keyed by the queue id `playlist-<id>` / `mylist-<id>`), and a History card for one resumes at its Current Video by the same rule (`buildTVCatalog`): while connected it reloads the List from the desktop first (`remote` with `resume`), in Offline mode it plays the Videos the TV holds. Every screen starts a queue through it; the queue's state lives in `stores/playback.ts`. It holds no desktop address: the TV player takes it from the Desktop connection and the phone player from the connection store's current `serverUrl`, when each Video starts.
- **Desktop fetch** — `services/desktop-fetch/` `desktopFetch.waitUntilFetched(serverUrl, videoId, { signal, onProgress })` asks the desktop to fetch a Video from YouTube and waits until it serves the file (a 200 or 206; a 202 means the desktop lost the file and is fetching it again), rejecting with `DesktopFetchFailedError` or, after 10 minutes, `DesktopStillFetchingError`. The Download queue and the Playback source wait through it; don't poll the desktop's download status anywhere else.
- **TV player** — `services/playback-source/` decides what the TV player plays: `playbackSource.useSource({ videoId, queue, index, getPosition })` returns the source (`preparing` with progress, `offline` with `resumeAt`, `stream`, `failed` with a typed failure and `canRetry`, or `desktopLost` with the next held Video's index or null), `upNext` for the warmed next Video, and `retry`. The desktop's address comes only from the Desktop connection, never the Play queue. When the desktop drops out mid-Stream, the source becomes the Offline copy at the same position, else `desktopLost`; the screen then plays the next held Video or goes back. If it drops out while the Video is still preparing, the source stays on that Video (`notOnThisTV`) and prepares it again when the desktop is back. The screen words failures with `components/tv/tvMessages.ts` and keeps navigation and the remote overlay; `components/tv/remoteKeys.ts` `decideRemoteKey` decides what each remote key does to the overlay (wake it, seek, hide it, keep it showing), and the screen keeps the auto-hide timer and the focus graph. A short notice that outlives the screen raising it goes through `stores/tvNotice.ts`; `TVNoticeHost` in `app/(tv)/_layout.tsx` shows it for a few seconds without taking focus.
- **Audiobooks** — never Videos (ADR-0004): they stay out of the library, the Play queue, the Download queue and Offline copies. `services/audiobook-catalog/` `audiobookCatalog.load(serverUrl)` returns the desktop's Audiobooks parsed with the contract's `audiobookCatalogSchema`, or none on a desktop older than `AUDIOBOOKS_SYNC_PROTOCOL_VERSION`; `components/phone/AudiobooksRow.tsx` holds the phone Home rows Audiobooks (it loads the catalog into `stores/audiobookCatalog.ts`, saved between launches) and Continue listening, both also in Offline mode; long-press or ⓘ opens the book screen `app/(mobile)/audiobook.tsx?id=` (jump to a Track, Start over). `services/book-player/` `bookPlayer.play(book, from?)` plays a book from a Listening position (`{trackId, seconds}`), Track after Track in Track order, skipping missing Tracks, until the last one ends (`finished`); a Track with no source now is `unavailable`. `jumpTo(book, index)` and `startOver(book)` start elsewhere; `previousTrack()` (restarts the Track when more than 3 s in, else the Track before; at the first Track, restarts it) and `nextTrack()` (at the last Track, finishes the book) move between Tracks, skipping missing ones; `listeningPosition()` says where the listener is. The book player screen has previous/next Track beside ±30s and a Tracks sheet (`components/phone/BookTracksSheet.tsx`, tapping a Track calls `bookPlayer.playTrack(index)`), and a bar for the Track (`useTrackProgress()`, `bookPlayer.seekTo` within the Track, reusing `components/phone/PlayerProgressBar.tsx`) above the time left in the book at its speed (`timeLeftInBook` in `apps/shared/book-player/`, shared with the desktop bar; hidden when a Track still to play has no known length); the lock screen keeps only ±30s. The Book player (`createBookPlayer`, `fakeBookAudioPlatform`, `localFirstTrackUri`) and the listening keeper (`keepListeningPosition`, which marks each save `meaningful` — play, pause, Track change, finish — or `periodic`, every 15 s while playing) live in `apps/shared/book-player/` for the desktop to share; their tests stay in this Jest suite (`package.json` `jest.modulePaths` resolves shared code's imports from this app's `node_modules`). `services/book-player/keepListeningPosition.ts` keeps every save in `stores/listeningPositions.ts` and POSTs it to the desktop; the Device report carries every kept position. `services/listening-position/` decides where a tap resumes (`resumePoint`: the newest of the desktop's and the phone's position, by the shared rule in `apps/shared/listening-position.ts`; a finished book starts over) and the Continue listening row (`continueListening`). Each Track keeps its own Track position (ADR-0006): the shared player resumes a picked Track (`jumpTo`, `playTrack`) and the Listening Track of Play book at it, from 0 once played to its end, and tells `onTrackPosition` each time playback leaves a Track; Start over clears them. The phone keeps them in `stores/trackPositions.ts` (also fed by every Listening save; `withKeptTrackPositions` in `services/listening-position/trackPositions.ts` takes the newest of the catalog's and the phone's), POSTs them live to a desktop known to speak `RESUME_SYNC_PROTOCOL_VERSION`, and the Device report's `resume` group carries them; the book screen and the Tracks sheet show each Track's state (`TrackListenBadge`). `useBookPlayerState()` feeds `app/(mobile)/book-player.tsx`. `createBookPlayer(platform)` is tested with `fakeBookAudioPlatform`; the platform decides where each Track plays from (`trackUri`, built with `localFirstTrackUri`: the Track's file on the phone when held, else the desktop Stream) and owns the audio output.
- **Held Audiobooks** — `services/held-audiobooks/` holds whole Audiobooks on the phone. `bookPlayer.play`, `jumpTo` and `startOver` also call `heldAudiobooks.pull(book)`, which fetches every Track that isn't missing, one at a time, into an `audiobooks/<bookId>/` folder of the Storage location (beside `videos/`, so Offline copy scans never see them), whenever the desktop is connected, in the background too for as long as the process lives (expo-audio's background playback keeps it alive while a book plays); only a disconnect pauses it. A Track cut short keeps its bytes in `audiobooks/<trackId>.download` in the app's storage and carries on from there (an `expo-file-system/legacy` resumable download with a Range request), also after an app restart; removing the book discards them. Each held book's cover is fetched first and kept in the app's own `audiobook-covers/` folder (always `file://`: the lock screen loads artwork through `java.net.URL`, which can't read `content://`), refetched when the desktop's cover URL changes and dropped when the book loses its cover; the Hold's `coverUri` is it. `AudiobookCover` (the rows, the book screen, the book player) and the lock-screen artwork pick the cover with `localFirstCoverUri`: the phone's copy, else the desktop's while connected. Each hold carries its reasons (`pulled`, `mirrored`): `remove(bookId)` is Remove from this phone (deletes the phone's files, never the desktop's), `release(bookId, reason)` drops one reason and deletes only when none is left, so the Audiobook Mirror never deletes a pulled book. Holds persist in AsyncStorage with a full `Audiobook` snapshot each, so held books resume and show on the book screen with no desktop. `components/phone/audiobooksRowItems.ts` decides the Audiobooks row's cards: the desktop's catalog (in Offline mode the saved `stores/audiobookCatalog.ts`), via `useAudiobookItems(serverUrl)`, which both rows and the book screen use, then held books it no longer lists, marked On this phone or, in Offline mode, Needs the desktop (dimmed, tap does nothing). The book screen shows how much is on the phone and Remove from this phone (`components/phone/AudiobookOnThisPhone.tsx`). Audiobooks never go through the Download queue or the Offline copy module.
- **Audiobook Mirror** — `services/audiobook-mirror/` runs inside every Device mirror sync on the phone (a TV holds no Audiobooks; it also syncs on the `sync:audiobooks` SSE event). `planAudiobookMirror({ sentIds, holds })` decides `hold` (sent books not held, or held for the Mirror) and `release` (books held for the Mirror that are no longer sent or were forgotten on the desktop); a book the user pulled is never claimed or released. `createAudiobookMirror` applies it with `heldAudiobooks.hold(book, "mirrored")` / `release(id, "mirrored")`, does nothing on a desktop too old to serve Audiobooks (`audiobookCatalog.served` → null), keeps each catalog it loads in `stores/audiobookCatalog.ts` (so an open phone shows a Listening position the desktop just announced), and gives the Device report its `heldAudiobookIds` (books wholly on the phone).
- **Audio library** — books play through `expo-audio` (one `createAudioPlayer`, `replace()` per Track), not `expo-video`. Chosen over `react-native-track-player` because it is the Expo SDK 55 module (new architecture, no extra native setup) and has what books need: background playback (`shouldPlayInBackground` plus the `expo-audio` config plugin's `enableBackgroundPlayback`, in `app.json`), lock-screen and notification controls (`setActiveForLockScreen` with title/artist/artwork and seek buttons; required on Android for playback past ~3 minutes in the background), speed (`setPlaybackRate` with pitch correction) and audio focus (`interruptionMode: "doNotMix"`). Track-player's queue isn't needed: the Book player owns the Track order. `services/book-player/index.ts` turns on background playback and lock-screen controls (title, Track, cover, play/pause, ±30s); the Book player owns ±30s across Track boundaries (`skip`), speed (`setSpeed`, 0.75×–2×, persisted in `stores/bookSpeed.ts` and re-applied at every Track) and skips a Track that fails or isn't ready within 20 s (two in a row → `unavailable`, so a lost desktop doesn't rush to the end). `expoAudioStatus.ts` turns expo-audio statuses into ended / ready / failed / system play-pause events, since Android emits no error for a 404 and pauses natively on audio-focus loss. `patches/expo-audio+55.0.18.patch` (patch-package, applied on `npm install`) makes the native lock-screen seek 30 s and pauses when headphones are unplugged (`setHandleAudioBecomingNoisy`); the lock-screen seek stays within the Track. SDK 55 links expo-audio as a prebuilt AAR (`node_modules/expo-audio/local-maven-repo`) that ignores the patched source, so `package.json` sets `expo.autolinking.android.buildFromSource: ["expo-audio"]` to compile it from source; drop that and the patch silently stops applying. Bumping expo-audio means regenerating that patch.
- **Movies** — never Videos (ADR-0005): they stay out of the library, the Play queue, the Videos' Download queue, the Video Offline copies and the Video watch history. `services/movie-catalog/` `movieCatalog.load(serverUrl)` returns the desktop's Movies and Series (`movieCatalogSchema`), or none on a desktop older than `MOVIES_SYNC_PROTOCOL_VERSION`; `components/phone/MoviesRow.tsx` loads it into `stores/movieCatalog.ts` (saved between launches) and shows the Movies Home row (`moviesRowItems`: missing Movies left out, dimmed Needs the desktop in Offline mode). Tapping one opens `app/(mobile)/movie-player.tsx?id=`, which plays through `phoneMoviePlaybackSource`, the Playback source in Stream-only mode (`desktopFetch: null`: plays the Movie Offline copy when there is one, else Streams at once; never fetches, warms or Downloads). Progress is kept in `stores/movieWatch.ts` and goes to the desktop as the Device report's `movieWatch`; `services/movie-watch/` `resumeAt` picks where a tap starts (the newer of the desktop's Watch state and the phone's, the start again once ~90% was reached) and `watchStateOf` says unwatched / in progress / watched by the same rule (a desktop mark made after the phone last played wins). Series: `components/phone/SeriesRow.tsx` (`seriesRowItems`) opens `app/(mobile)/series.tsx?id=` (Seasons and Episodes; Play Streams the next-up Episode from `seriesNextUp` in `services/movie-watch/seriesWatch.ts`, which applies the shared `apps/shared/series/nextUp.ts` from the Series' last Episode: the newer of the desktop's and this Device's, or, on a desktop older than `RESUME_SYNC_PROTOCOL_VERSION`, the Episode in progress that changed last); starting an Episode on either player (`hooks/useLastEpisodeWhenStarted.ts` → `services/series-last-episode/`) keeps it in `stores/seriesLastEpisodes.ts` (the Device report's `seriesLastEpisodes`) and POSTs it live to `/api/series/:id/last-episode` while connected to a desktop that speaks resume. `services/desktop-protocol/` remembers the desktop's sync protocol version, which the Device mirror learns on every sync; live sends ask `desktopProtocol.known`, and the mirror's report leaves out every resume field for an older desktop. Episodes play in the same player as `movie-player?kind=episode&id=` through `phoneEpisodePlaybackSource` and autoplay the next one (`seriesEpisodeAfter`). Continue watching is drawn by `components/phone/ContinueWatchingRow.tsx` above the other rows: `mergeContinueWatching` (`components/phone/continueWatching.ts`) merges the Video rows' Continue watching Videos, Movies in progress and each started Series' next-up Episode, newest first; a Series leaves once no unwatched Episode remains. Both players keep progress with `hooks/useMovieProgressRecorder.ts`. **Held Movies** — a Download happens only when the desktop sent the title or the user long-presses a Movie card, or an Episode on the Series screen, for "Download to this phone" (`components/phone/movieOnThisPhone.ts` `showMovieOptions`, with `heldTitleOfMovie` / `heldTitleOfEpisode`; an Episode is held as "Series · Episode" with the Series poster). `services/held-movies/` `heldMovies` keeps each held Movie or Episode with its reasons (`pulled`, `mirrored`) and what it shows of it (title, poster URL) in the SQLite `held_movies` table: `pull(title)`, `hold(title, reason)`, `release(id, reason)` (deletes only when no reason is left, so the Mirror never deletes a pulled title), `remove(id)` (Remove from this phone), `holds()` / `useHolds()`, `heldIds()` (`{movieIds, episodeIds}` with an Offline copy, for the Device report). Files come through `movieDownloadQueue`, a second instance of the Download queue with `desktopFetch: null` (the file is on the desktop already; it transfers from `api.getMovieFileUrl` / `getEpisodeFileUrl` by the hold's kind), into `movieOfflineCopy`, a second instance of the Offline copy module with `folder: "movies"` (beside `videos/` in every Storage location, including a USB folder; records in `held_movies.local_path`). Movie and Episode ids share it (desktop UUIDs). **Movie Mirror** — `services/movie-mirror/` runs inside every Device mirror sync on the phone, after `refreshCatalog` (which returns null on a desktop too old to serve Movies, and then the Mirror does nothing): `sentTitles(catalog)` lists one entry per sent file (each sent Movie and every Episode of each sent Season; the desktop sends a Series one Season at a time, and Episodes a Rescan adds to a sent Season are listed with it), `planMovieMirror({ sent, holds })` decides `download` (sent, not missing, not held or held for the Mirror) and `release` (held for the Mirror and no longer sent or no longer in the catalog, e.g. switched off Shown on Devices); `createMovieMirror({ held, captions })` applies it, then keeps the Captions of every title with an Offline copy that the catalog lists (`services/movie-captions/` `keptCaptions`: each Caption's WebVTT in the app's own `movie-captions/<titleId>/` folder, fetched once, dropped when the desktop no longer pairs it, forgotten with the hold); `captionCues.load(serverUrl | null, titleId, captionId)` reads the kept copy first, so held titles show Captions in Offline mode on the phone and the TV. On this phone shows held Movies before its Videos (`PhoneHomeRow.movies`, `components/phone/HeldMovieCards.tsx`; long-press removes); the Movies row, the Series row and Continue watching dim only titles with no Offline copy in Offline mode. The TV Mirrors the same way, onto its own Storage location (including a USB folder), and `tvMoviePlaybackSource` / `tvEpisodePlaybackSource` play the `movieOfflineCopy` when there is one. On the TV, `buildTVCatalog` adds a Movies tab (hidden while it has no cards, as on an older desktop; in Offline mode only the Movies the TV holds, from the saved catalog plus held ones it no longer lists, via the `heldTitles` input that `hooks/useHeldTitles.ts` gives) whose cards open `app/(tv)/movie/[id].tsx`, which Streams through `tvMoviePlaybackSource`, puts the Movie in TV history and words problems with `describeMovieProblem` (including `playerRejected`, when expo-video's `statusChange` reports an error: "Can't play this on this TV"). TV history (`stores/tvHistory.ts`, pure rules in `stores/tvHistoryEntries.ts`) holds `kind: "videos"` queues and `kind: "movie"` / `kind: "series"` entries; a title entry keeps no position, so its card resumes from the Watch progress at press time (a Series card plays its `seriesNextUp` Episode, or opens the Series once all are watched). A Series tab (hidden like Movies) opens `app/(tv)/series/[id].tsx`: Seasons as tabs, Episodes as a D-pad list from `components/tv/tvSeries.ts` `buildTVSeriesView`, focused on the next-up Episode; in Offline mode the Series tab, the Series screen and Episode autoplay see only the Episodes the TV holds (`heldSeries` in `tvCatalog.ts`). The TV Movie player also plays Episodes (`movie/[id]?kind=episode`, `tvEpisodePlaybackSource`), records their Series in History and autoplays `seriesEpisodeAfter`; both players find their title with `findTitle` in `services/movie-watch/seriesWatch.ts`.
- **Persistence** — SQLite via expo-sqlite + Drizzle (`db/schema.ts`, `db/repositories/`); migrations run on app start. Zustand stores in `stores/`; `library.ts` mirrors SQLite, the rest persist to AsyncStorage.
- **P2P sharing** — `services/p2p/`: mDNS discovery (react-native-zeroconf) plus a local server/client. The server serves Offline copies via `offlineCopy.readBytes`; the client downloads to a temp file and the share screen calls `adopt`.
- **File system** — prefer the expo-file-system SDK 54+ `Paths`/`Directory`/`File` API for new code; `storage-location.ts`, the Download queue platform, `app-update.ts`, the Offline copy platform and the Held Audiobooks platform still use `expo-file-system/legacy` (picked-folder `content://` URIs, which only the legacy SAF API writes). The Offline copy and Held Audiobooks platforms share their Storage location file helpers (`isContentUri`, `joinUri`, `documentsDir`, `ensureDir` for SAF or `file://`, `fileExists`, `removeFile`) from `services/storage-files.ts`.

## Offline copies

`services/offline-copy/` owns a Video's Offline copy in every Storage location (internal, picked folder, USB folder): `offlineCopy.getUri(videoId)`, `offlineCopy.useUri(videoId)`, `offlineCopy.useLookup()` (a `getUri` for screens checking many Videos, re-rendering on any change), `offlineCopy.readBytes(videoId)` for peer-to-peer serving, `adopt` for finished Downloads and peer-to-peer receives, and `remove` for Videos deleted from the library (`stores/library.ts`). It is the only writer of the videos table's `localPath` record; the app shell (`hooks/useOfflineCopyScans.ts`) triggers its scans. Choosing a Storage location stays in `services/storage-location.ts`.

TV screens, phone screens and `VideoGridCard` ask the module: `useUri` / `useLookup` for anything rendered, and `getUri` (or the `useLookup` function, which reads through to it) in handlers and wait loops. Nothing else carries a location: the Play queue (`StreamingVideo`), TV history, watch history and the library `Video` have none, and players resolve the Offline copy when each Video starts. The Offline copy module is the one way to find a Video's file: don't build video file paths or check for their existence outside `services/offline-copy/`.

## Theme

Styling tokens come from `theme/` (`colors`, `spacing`, `radius`, `fontSize`, `fontWeight`), matching the desktop dark palette; icons come from `theme/icons.ts` (lucide-react-native). Use these tokens in `StyleSheet.create` rather than literal colors or sizes. TV screens add `theme/tv.ts`: `tvFontSize` for viewing across a room, and `tvFocus` / `tvRestingBorder`, the one focus treatment (a white ring) every focusable TV element uses.
